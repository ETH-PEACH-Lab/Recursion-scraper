Intuition

The problem asks us to evaluate a boolean expression with different operators such as ! (NOT), & (AND), and | (OR), and simple boolean literals t (true) and f (false). The key observation here is that the operators act on sub-expressions enclosed within parentheses, and we need to evaluate these inner expressions first before applying the outer operators.

The most natural way to handle this nested structure is by using a stack data structure. We can process the expression character by character, pushing elements onto the stack until we hit a closing parenthesis ). At that point, we pop the stack and evaluate the sub-expression, and push the result back onto the stack. This helps manage the nested nature of the expressions efficiently.

Approach

  1. Stack Usage:
    - Traverse the expression character by character.
    - When encountering t, f, or an operator like !, &, or |, we push them onto the stack.
    - When encountering a closing parenthesis ), we pop elements from the stack until reaching an opening parenthesis (. These elements form the sub-expression to evaluate.
    - Depending on the operator just before the (, we evaluate the sub-expression:
    • !: Apply NOT to a single value.
    • &: Apply AND to all values.
    • |: Apply OR to all values.
    • Push the result of this sub-expression evaluation back onto the stack.
  2. Efficiency: This approach ensures we only traverse the string once and evaluate each sub-expression exactly once, giving us an efficient solution.

Complexity

  • Time complexity:
    The time complexity is O(n), where \(n\) is the length of the input expression, as we iterate through each character of the expression and perform constant-time operations (pushing, popping) on the stack.

  • Space complexity:
    The space complexity is O(n) because, in the worst case, the entire expression could be pushed onto the stack.

class Solution {
public:
bool parseBoolExpr(string expression) {
stack st;

    for (char c : expression) {
        if (c == ')') {
            vector<char> subExpr;
            while (st.top() != '(') {
                subExpr.push_back(st.top());
                st.pop();
            }
            st.pop(); // Remove '('

            char op = st.top();
            st.pop(); // Remove the operator

            if (op == '!') {
                st.push(subExpr[0] == 't' ? 'f' : 't');
            } else if (op == '&') {
                char result = 't';
                for (char e : subExpr) {
                    if (e == 'f') {
                        result = 'f';
                        break;
                    }
                }
                st.push(result);
            } else if (op == '|') {
                char result = 'f';
                for (char e : subExpr) {
                    if (e == 't') {
                        result = 't';
                        break;
                    }
                }
                st.push(result);
            }
        } else if (c != ',') {
            st.push(c);
        }
    }

    return st.top() == 't';
}

};

stack := []rune{}

for _, c := range expression {
    if c == ')' {
        subExpr := []rune{}
        for stack[len(stack)-1] != '(' {
            subExpr = append(subExpr, stack[len(stack)-1])
            stack = stack[:len(stack)-1]
        }
        stack = stack[:len(stack)-1] // Remove '('

        op := stack[len(stack)-1]
        stack = stack[:len(stack)-1] // Remove operator

Step-by-Step Detailed Explanation

  1. Initialize a Stack: We use a stack to store each character of the expression as we parse it. This helps us handle the nested structure of the boolean expression.

  2. Iterate Through the Expression: As we iterate through the expression:
    - If the current character is a closing parenthesis ), we pop characters off the stack until we hit the corresponding opening parenthesis (.
    - We then evaluate the sub-expression inside the parentheses based on the operator just before ( (either !, &, or |).

  3. Evaluate Sub-expression:
    - For !, we negate the boolean value.
    - For &, if any of the sub-expressions is false (f), the result is false.
    - For |, if any of the sub-expressions is true (t), the result is true.

  4. Push the Result Back: After evaluating the sub-expression, we push the result (either t or f) back onto the stack.

  5. Final Result: At the end of the iteration, the stack will contain the final boolean value, which is the result of the entire expression.contain the final boolean value, which is the result of the entire expression.
