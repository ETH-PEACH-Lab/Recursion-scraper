The problem asks us to find all the possible results from computing the expression with different ways of parenthesizing it.

Intuition #1 ( Recursion, Divide and Conquer )

  • Since the expresion only contains numbers and basic operators +, -, *, we can recursively approach it !
  • Ever heard of Divide and Conquer? Yes, you might have studied in your college courses. that is exactly what we are going to do now.
  • Recursively break it down based on where the operators appear, evaluate each possible sub-expression, combine the results

Approach #1 ( Recursion, Divide and Conquer )

  • Recursively divide the expression: Treat each operator +, -, * as a potential point to split the expression into two smaller sub-expressions.
  • Conquer the sub-expressions: Recursively compute all possible values of left and right sub-expressions
  • Merge the results: For each valid split, combine the results of the left and right parts using current operator at the split

Example Walkthrough:

Let's use the expression 2*3-4*5 as an example.

  1. First Iteration: We loop through the expression, and at index 1, we encounter the * operator. So, we split it into two parts:
    - Left part: 2
    - Right part: 3-4*5

Then, we recursively compute the results for both sides.

  1. Left Part (2): Since this is just a number, the result is [2].

  2. Right Part (3-4*5): We now recursively split this further. At index 1 in this sub-expression, we find the - operator, so we split it into:
    - Left part: 3
    - Right part: 4*5

Recursively compute both sides:
- Left part: 3 results in [3]
- Right part: 4*5 results in [20]

Now combine the results for 3-20:
- 3 - 20 = -17
So, the right part 3-4*5 yields [-17].

  1. Combining: Now combine the left part 2 and the right part [-17] using the * operator:
    - 2 * -17 = -34

At this point, we’ve found one possible result: -34.

  1. Exploring other splits: Continue exploring other operators (- and * in 2*3-4*5) in a similar manner to find more possible results.

Explanation of Code:

  • Base Case: If the expression has no operator (e.g., "2"), it will return the integer value of the expression (result.append(int(expr))).

  • Recursive Splitting:

  • For every character in the expression, if it is an operator (+, -, or *), we split the expression into two parts:
    • left = helper(expr[:i]): Recursively compute the results of the left sub-expression.
    • right = helper(expr[i+1:]): Recursively compute the results of the right sub-expression.

  • We then combine the results of the left and right sub-expressions using the current operator (+, -, or *) and append these results to our result list.

  • Merging Results: Once all possible splits are evaluated, we return the list of results.

Complexity #1:

  • Time complexity: The time complexity is exponential O(2^n), where n is the number of characters in the expression. This happens because for every operator, we explore multiple possible combinations of the left and right sub-expressions, and we do this recursively for every split.

  • Space complexity: O(2^n)
    The algorithm stores the intermediate results at each step. And the total number of results can be equal to the O(2^n)

Code #1: Naive Recursion

```python []
class Solution:
def diffWaysToCompute(self, expression: str) -> List[int]:

    def helper(expr):
        result = []
        for i, char in enumerate(expr):
            if char in "+-*":
                left = helper(expr[:i])
                right = helper(expr[i+1:])

                for l in left:
                    for r in right:
                        if char == '+':
                            result.append(l + r)
                        elif char == '-':
                            result.append(l - r)
                        else:
                            result.append(l * r)

        if not result:
            result.append(int(expr))

        return result

    return helper(expression)

    private List<Integer> helper(String expr) {
        List<Integer> result = new ArrayList<>();
        for (int i = 0; i < expr.length(); i++) {
            char charAt = expr.charAt(i);
            if (charAt == '+' || charAt == '-' || charAt == '*') {
                List<Integer> left = helper(expr.substring(0, i));
                List<Integer> right = helper(expr.substring(i + 1));
                for (int l : left) {
                    for (int r : right) {
                        if (charAt == '+') {
                            result.add(l + r);
                        } else if (charAt == '-') {
                            result.add(l - r);
                        } else {
                            result.add(l * r);
                        }
                    }
                }
            }
        }
        if (result.isEmpty()) {
            result.add(Integer.parseInt(expr));
        }
        return result;
    }
}

Intuition #2: Dynamic Programming (Memoization, Top-down DP, Recursion)

When we have a recursive solution that computes results by splitting the expression into different parts, some subexpressions get computed repeatedly. Memoization is a powerful tool to optimize this process. By storing the results of each subexpression, we avoid recomputing them and significantly reduce the time complexity.

The idea is to use a dictionary (or hash map) to store already computed results for each subexpression. This allows us to efficiently retrieve precomputed results, rather than re-evaluating the same subexpression multiple times.

Approach #2: Top-down DP with Memoization ( Caching )

  1. Recursive Splitting: As in the naive approach, split the expression around each operator, recursively calculate the results for both sides, and combine them.

  2. Memoization: Store the results for every subexpression that gets computed. If a subexpression has already been evaluated, retrieve its value from the memo instead of recalculating it.

  3. Combination: For each operator, compute the left and right subexpressions, then combine the results using the corresponding operator.

This results in a more efficient solution with optimal time complexity, as each subexpression is computed only once.

Example

Consider the expression "2*3-4*5":

  1. We start by splitting the expression at each operator:
    - Split at *: We compute 2 * (rest of the expression).
    - Split at -: We compute (result of left side) - (result of right side).
    - Continue recursively splitting each subexpression.

  2. Once subexpressions are computed, memoization ensures that we reuse results for identical subexpressions, speeding up the process.

Complexity #2:

  • Time Complexity: For the naive recursion, it's O(2^n), it reduces to O(n^3)
  • Space Complexity: We store the result for every possible sub-expression, and there can be about O(n^2) sub-expressions (since every pair of positions in the string can form a sub-expression).

Code #2: Memoized Dynamic Programming Solution

Note: In python, you can either do memoization manually or utilize an in-built decorator called @lru_cache(None)( Least recently used cache ). @lru_cache(None) speeds up function execution by storing and reusing previous results, and None means it won’t discard any cached results based on their number i.e., No capacity limit.

    if (memo.containsKey(expr)) {

                        result.add(l - r);
                    } else {
                        result.add(l * r);
                    }
                }
            }
        }
    }

    if (result.isEmpty()) {
        result.add(Integer.parseInt(expr));
    }

    memo.put(expr, result);
    return result;
}

# Intuition #3 (Tabulation, Bottom-Up)
**Understanding Tabulation (Bottom-Up)**
Tabulation, also known as bottom-up dynamic programming, is a technique where you solve the problem by building up solutions from smaller subproblems. Instead of solving the problem recursively and relying on memoization, you iteratively compute the solution to each subproblem and store these solutions in a table (usually an array or matrix) to avoid redundant computations.

In this problem, the idea is to use a table to keep track of the results for different subexpressions, ensuring that we systematically build up solutions for increasingly larger subproblems.

# Approach #3: ( DP Table, Iterative Approach )
1. **Expression Parsing:** The expression is parsed into two lists: nums (numbers) and ops (operators).
2. **2D DP Table Setup:** A 2D list `dp[i][j]` is used to store possible results for subexpressions from index i to j.
3. **Initialization:** The diagonal of the dp table is initialized with single numbers because any subexpression of length 1 is just the number itself.
4. **Filling the DP Table:** For every subexpression of length 2 or more, we calculate the results by breaking it at every operator `(+, -, *)`, and combining the results of the left and right subexpressions.
5. **Final Answer:** The answer for the full expression is stored in dp[0][n-1].

**Example:**
For the expression `"2-1-1"`, the table would store intermediate results of expressions like `"2-1"` and `"1-1"`. These results are then combined to find the results of larger subexpressions until we get the final result.

# Code #3: Tabulated Dp Solution
```python []
class Solution:
    def diffWaysToCompute(self, expression: str) -> List[int]:
        nums, ops = [], []
        i = 0
        while i < len(expression):
            if expression[i].isdigit():
                num = 0
                while i < len(expression) and expression[i].isdigit():
                    num = num * 10 + int(expression[i])
                    i += 1
                nums.append(num)
            else:
                ops.append(expression[i])
                i += 1

        n = len(nums)
        dp = [[[] for _ in range(n)] for _ in range(n)]

        for i in range(n):
            dp[i][i] = [nums[i]]

        for length in range(2, n + 1):
            for i in range(n - length + 1):
                j = i + length - 1
                dp[i][j] = []
                for k in range(i, j):
                    left_results = dp[i][k]
                    right_results = dp[k + 1][j]
                    operator = ops[k]

                    for left in left_results:
                        for right in right_results:
                            if operator == '+':
                                dp[i][j].append(left + right)
                            elif operator == '-':
                                dp[i][j].append(left - right)
                            else:
                                dp[i][j].append(left * right)

        return dp[0][n - 1]

class Solution {
public List diffWaysToCompute(String expression) {
List nums = new ArrayList<>();
List ops = new ArrayList<>();

    int i = 0;
    while (i < expression.length()) {
        if (Character.isDigit(expression.charAt(i))) {
            int num = 0;
            while (i < expression.length() && Character.isDigit(expression.charAt(i))) {
                num = num * 10 + (expression.charAt(i) - '0');
                i++;
            }
            nums.add(num);
        } else {
            ops.add(expression.charAt(i));
            i++;
        }
    }

    int n = nums.size();
    List<Integer>[][] dp = new ArrayList[n][n];

    for (int j = 0; j < n; j++) {
        dp[j][j] = new ArrayList<>();
        dp[j][j].add(nums.get(j));
    }

    for (int length = 2; length <= n; length++) {
        for (int l = 0; l <= n - length; l++) {
            int r = l + length - 1;
            dp[l][r] = new ArrayList<>();
            for (int k = l; k < r; k++) {
                List<Integer> leftResults = dp[l][k];
                List<Integer> rightResults = dp[k + 1][r];
                char operator = ops.get(k);

                for (int left : leftResults) {
                    for (int right : rightResults) {
                        if (operator == '+') {
                            dp[l][r].add(left + right);
                        } else if (operator == '-') {
                            dp[l][r].add(left - right);
                        } else {
                            dp[l][r].add(left * right);
                        }
                    }
                }
            }
        }
    }

    return dp[0][n - 1];
}

}

class Solution {
public:
    vector<int> diffWaysToCompute(string expression) {
        vector<int> nums;
        vector<char> ops;

        int i = 0;
        while (i < expression.size()) {
            if (isdigit(expression[i])) {
                int num = 0;
                while (i < expression.size() && isdigit(expression[i])) {
                    num = num * 10 + (expression[i] - '0');
                    i++;
                }
                nums.push_back(num);
            } else {
                ops.push_back(expression[i]);
                i++;
            }
        }

        int n = nums.size();
        vector<vector<vector<int>>> dp(n, vector<vector<int>>(n));

        for (int j = 0; j < n; j++) {
            dp[j][j] = {nums[j]};
        }

        for (int length = 2; length <= n; length++) {
            for (int l = 0; l <= n - length; l++) {
                int r = l + length - 1;
                for (int k = l; k < r; k++) {
                    const auto& leftResults = dp[l][k];
                    const auto& rightResults = dp[k + 1][r];
                    char op = ops[k];

                    for (int left : leftResults) {
                        for (int right : rightResults) {
                            if (op == '+') {
                                dp[l][r].push_back(left + right);
                            } else if (op == '-') {
                                dp[l][r].push_back(left - right);
                            } else {
                                dp[l][r].push_back(left * right);
                            }
                        }
                    }
                }
            }
        }

        return dp[0][n - 1];
    }
};

Complexity #3:

  • Time Complexity: O(n^3) - For each subexpression, we iterate over all operators, leading to a cubic time complexity due to nested loops.
  • Space Complexity: O(n^2) - The space complexity is proportional to the number of subexpressions stored in the table, which is O(n^2).

Tabulation is efficient for problems with overlapping subproblems and optimal substructure, where it systematically builds solutions from the ground up. It avoids the overhead of recursion, recursion stack space and can often reduce space complexity by using iterative loops and space-saving techniques.
