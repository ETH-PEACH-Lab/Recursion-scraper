解题思路

一般的递归思路是直接递归然后得到为n时的整个字符串，再在字符串中找位置为k的字符，无疑这在时间空间上消耗都是巨大的。但是借鉴这个思想，我们是否可以只递归去找位置为k处的字符？
根据题意，
S1 = "0"
当 i > 1 时，Si = Si-1 + "1" + reverse(invert(Si-1))
在第n个字符串的k的位置可以分为3种情况讨论。
第一种是当k小于Si-1字符串的长度的时候，Si字符串的k位置的字符和Si-1字符串k位置的字符是一致的；
第二种是当k恰好等于Si-1字符串的长度+1的时候，这时候k为'1';
第三种是当k大于Si-1字符串的长度的时候，需要经过翻转和反转两个操作。
首先看反转，假设Si字符串的长度为m，k在反转之前的位置为m-k+1;相当于从头遍历改为从尾遍历，但最中间的'1'是不做操作的，所以多减了一位，所以要再加上1.

此时，Si字符串在k位置转为Si在m-k+1的位置的字符翻转。然后往下递归，转化为求取Si-1在m-k+1位置的字符翻转。
再来看翻转操作，当k大于Si-1字符串的长度的时候，就要进行翻转，所以额外添加一个翻转参数reverse来帮助计算在递归过程中一共翻转了几次。
最后在递归结束的时候，需要对递归结果进行翻转的判断，根据reverse，如果reverse为奇数次，则需要进行翻转，为偶数次则翻转抵消。
还有一个问题就是序数为n的时候字符串长度的计算，通过规律可知，字符串的长度为2的n次幂-1；
代码还有许多可以优化的地方，大家随意看看。

代码

class Solution {
    //翻转次数;
    int reverse=0;
    public char findKthBit(int n, int k) {
        char reResult=find(n,k);
        //翻转为奇数次，要对递归结果进行翻转;
        if(reverse%2==1){
            if(reResult=='0'){
                reResult='1';
            }else{
                reResult='0';
            }
        }
        return reResult;
    }
    public char find(int n,int k){
        //初始条件是S1='0';
        if(n==1)return '0';
        //序号n的字符串长度m为2的n次幂-1，恒为'1'的项就为m/2+1,由于m恒为奇数，所以比较条件转化为2的n-1次幂
        if(k==(int)Math.pow(2,n-1)){
            return '1';
        }else if(k>(int)Math.pow(2,n-1)){
            k=(int)Math.pow(2,n)-k;
            reverse+=1;
            --n;
            return find(n,k);
        }else{
            --n;
            return find(n,k);
        }
    }


}
