Intuition

Recursively parse the expression until it is decomposed into "t" and "f" characters, which translate to TRUE and FALSE respectively. Build the final solution by applying the operators on every subexpression.

Optimizations

The identity element (the element which does not change the result) of the AND operator is TRUE, and for the OR operator it is FALSE. Since there are only 2 possible values, if we encounter the value which is not the identity element for the current operator while parsing the operands, we can exit early as there is no way to change the result.

When a subexpression's length is 1, it is either "t" or "f", so we can evaluate this without the overhead of an extra function call.

Caching subexpression values avoids evaluating the same subexpression multiple times.

class Solution:
def parseBoolExpr(self, expression: str) -> bool:
# caching only provides minimal speed gain on the size of the test cases, but the memory impact is also negligible, feel free to comment/uncomment the @cache as you prefer

    # parse expression between low and high indices
    @cache
    def parse(low, high):
        # expression is a single character, it can only be "t" or "f"
        if low == high - 1:
            return expression[low] == "t"

        # the operator is the first character in any expression longer than 1 character
        operator = expression[low]

        # if the operator is NOT, then there is only 1 operand, so parse this operand
        if operator == "!":
            return (
                not parse(low + 2, high - 1)
                if high + 1 - low
                else "t" == expression[low + 2]
            )

        # current open parantheses count
        pc = 0

        # currently considered subexpression start index
        # first position is always the operator, second position is always an open parantheses, so start from third position
        sub_low = low + 2

        # search subexpressions inside the bounds of the current expression
        for sub_high in range(low + 2, high):
            # character at position sub_high
            ch = expression[sub_high]

            # if we found a comma and we are not inside any pair of parantheses, we found a subexpression
            if ch == "," and not pc:
                # evaluate the found subexpression
                # if the length of the considered subexpression is 1, we know the result so there is no reason to make another function call
                res = parse(sub_low, sub_high) if sub_high - sub_low - 1 else "t" == expression[sub_low]

                # the identity element (the element which does not change the result) of the AND operator is TRUE, and for the OR operator it is FALSE
                # if the operator is AND, once we found a FALSE value, there is no point in searching further as there is no way to make the subexpression evaluate to anything else
                if operator == "&" and not res:
                    return False
                # same for OR if we find a TRUE value
                elif operator == "|" and res:
                    return True
                else:
                # the next subexpression to be considered starts after the comma
                    sub_low = sub_high + 1
            # increment parantheses count if we found an open parantheses, or decrement it if we found a closed parantheses
            elif ch == "(":
                pc += 1
            elif ch == ")":
                pc -= 1

        # the for exits before considering the subexpression after the last comma, so we need an extra call here for the remaining characters
        # apply same optimization as before
        return (
            parse(sub_low, high - 1) if high - 2 - sub_low else "t" == expression[sub_low]
        )

    # compute the result
    return parse(0, len(expression))
