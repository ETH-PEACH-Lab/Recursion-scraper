Intuition

Without * and . the problem is reduced to a simple string comparison problem. Does s1 equal s2? How does string comparison work under the hood? It iterates through both strings at the same time and compares them character by character.

Unlike standard string comparison, because this problem has the * character, the strings do not need to be the same length to match. This means that the index used to compare s1 to s2 does not need to be the same. Thus s1 has it's own index and s2 has its own index and we can compare the strings using their respective index.

We know that this problem can be neatly divided into smaller subproblems because once a character is matched, we only need to worry about the remaining characters. Similarly once a sub-pattern is used, we only need to focus on the remaining pattern.

I knew that because the problem involved * it would require us to test all of the possible matches for the character directly preceding the *. This is because the problem states it matches zero or more characters.

For example: a* could be '', a, aa, aaa, ... Thankfully this is bounded by the fact that s1 has a finite length and thus a finite number of matches.

With these ideas I knew that I wanted:
1. A brute force solution that checks all of the different possibilities of matches.
2. Recursive steps to neatly break down the problem into subproblems.

Approach

I knew that I wanted to create a recursive backtracking solution that depends on two indexes i and j corresponding to the indexes of s1 and s2.

Because of the * I knew that I wanted to iterate through both strings in reverse order and match starting from the last character. We don't need to do but this makes it easier to determine if the next character is a "kleene expression" when iterating. Seeing the * first makes it easier to determine that it's a "kleene expression" compared to a regular character.

Figuring out base cases is a great first step for figuring out recursive solutions. Let (i, j) represent the arguments to the backtracking function:

  1. If we reach the end of both strings, we know that we matched the entire input string so return True. Ex: (-1, -1) equivalent to s1 = "" and s2 = ""

  2. If we run out of patterns before the entire input string is matched return False. Ex: (1, -1) equivalent to s1 = "ab" and s2 = ""

  3. If we reach the end of string s1 but s2 still has remaining characters we need to determine whether the remaining characters are all "kleene expressions" or not.

    • If all remaining patterns are kleene sub-patterns then return True.
    • If not return False.
    • Ex: (-1, 3) could be something like s1 = "" and s2 = a*b* which should return True because * represents zero or more.
    • Or (-1, 3) could be something like s1 == "" and s2 = abab which should return False since you can't use the pattern to match and empty string.
    • Or (-1, 3) could be something like s1 == "" and s2 = ab.* which should return False since the pattern is not all "kleene expressions". You cannot match an empty string with ab.

Next step after creating the base cases is creating the actual recursive cases:

  1. If the current element is * we have two options either use the "kleene expression" or do not use the expression. This breaks down to:

    • Perform a zero match (not using the "kleene expression"). Thus the recursive case would be: backtrack(i, j - 2). Ex "a*" will skip to ""

    • To use the "kleene expression" we match once but keep the j index the same. The reason we keep the index the same is because * can match multiple times thus we might need it for multiple matches in other recursive calls. Thus the recursive case would be: backtrack(i - 1, j). Note We can only use the kleene expression if s1[i] equals the character at the start of the kleene expression.

  2. The last recursive case is a regular match.

    • if s1[i] == s2[j] or s2[j] == '.' then there's a match so move both iterators thus backtrack(i - 1, j - 1).

Complexity

  • Time complexity: O(MN) where M = len(s) and N = len(p) since I used a cache to memoize repeated subproblems.
  • Space complexity: O(M^2N). O(MN) for the cache multiplied by O(M) because of the recursive stack. The length of the stack is determined by the length of s since the base cases primarily revolve around s being empty.

Code

class Solution:
    def isMatch(self, s: str, p: str) -> bool:
        i, j = len(s) - 1, len(p) - 1
        return self.backtrack({}, s, p, i, j)

    def backtrack(self, cache, s, p, i, j):
        key = (i, j)
        if key in cache:
            return cache[key]

        # End of string
        if i == -1 and j == -1:
            cache[key] = True
            return True

        # no remaining patterns
        if i != -1 and j == -1:
            cache[key] = False
            return cache[key]

        # valid if pattern only consists of * matches
        if i == -1 and p[j] == '*':
            k = j
            # skip to next character
            while k != -1 and p[k] == '*':
                k -= 2

            # reached end of string
            if k == -1:
                cache[key] = True
                return cache[key]

            cache[key] = False
            return cache[key]

        # cannot fully match pattern
        if i == -1 and p[j] != '*':
            cache[key] = False
            return cache[key]

        if p[j] == '*':
            # zero match
            if self.backtrack(cache, s, p, i, j - 2):
                cache[key] = True
                return cache[key]

            # match
            if p[j - 1] == s[i] or p[j - 1] == '.':
                if self.backtrack(cache, s, p, i - 1, j):
                    cache[key] = True
                    return cache[key]

        if p[j] == '.' or s[i] == p[j]:
            if self.backtrack(cache, s, p, i - 1, j - 1):
                cache[key] = True
                return cache[key]

        cache[key] = False
        return cache[key]
