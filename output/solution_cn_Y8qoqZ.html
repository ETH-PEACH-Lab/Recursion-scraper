思路

解法1：迭代

由于两个链表的都是递增的，因此非常容易想到用两个指针分别扫描两个链表的节点，以此比较元素值，把较小的值插入到new出来的链表后

需要注意的是，这里引入伪头节点dum： 由于初始状态合并链表中无节点，因此循环第一轮时无法将节点添加到合并链表中。解决方案：初始化一个辅助节点dum作为合并链表的伪头节点，将各节点添加至dum之后；合并完成后返回的dum.next就是真正的第一个节点

```Python3 []

Definition for singly-linked list.

class ListNode:

def init(self, val=0, next=None):

self.val = val

self.next = next

class Solution:
def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
# iterative 较易想到
# 双指针扫+插入
cur = dum = ListNode(-1) # 设置哨兵节点，方便返回合并后的链表
# dum是一个dummy头节点，下一个才是真正的首节点
# cur是新链表的扫描节点

    while list1 and list2: # 扫描公共长度
        if list1.val < list2.val:
            cur.next = list1
            list1 = list1.next
        else:
            cur.next = list2
            list2 = list2.next

        cur = cur.next # 结果链表自己也得往下走

    # 剩余部分至多只有一个未被合并完，直接接到后面即可
    cur.next = list1 if list1 is not None else list2

    return dum.next # 返回真正的首节点


### 复杂度分析
时间复杂度：$o(M + N)$，M和N分别为list1和list2的长度；至多需要完全扫完两个链表才能完成合并
空间复杂度：$O(1)$，双指针只用开辟常数空间占用


## 解法2：递归

### 思路

递归方法在处理链表问题时尤其强大，因为它可以自然地将问题分解为更小的子问题，直到达到简单的基本情况。对于合并两个有序链表的问题，递归解法的直观性和简洁性来源于以下几点：

1. **问题分解**：合并两个链表可以分解为首先合并它们的头节点，然后递归地合并剩下的部分。这种方式将大问题转化为小问题，直至问题简化为足够简单的形式（基本情况）。

2. **重复操作**：无论是整个链表还是子链表，合并操作都是相同的——比较两个链表的当前节点，选择较小者作为合并链表的下一个节点，然后对剩余部分进行递归合并。这种重复性是递归方法得以应用的关键。

3. **基本情况处理**：当遇到任一链表为空的情况时，直接返回另一个非空链表。这是递归的终止条件，也确保了合并操作能够正确结束。

4. **简化代码复杂度**：递归方法避免了复杂的循环和指针操作，使代码更加简洁和易于理解。

### 代码实现

```Python3 []
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next
class Solution:
    def mergeTwoLists(self, list1: Optional[ListNode], list2: Optional[ListNode]) -> Optional[ListNode]:
        """
        recursive，分治思路，转化成更小的子问题，然后递归实现
        选出更小的节点，递归合并剩下的节点
        """
        l1, l2 = list1, list2
        if l1 is None: # 一条链表走完了，直接把另外一条尾部并在后面
            return l2
        elif l2 is None:
            return l1
        else:
            if l1.val < l2.val: # 选择较小的头节点，递归合并剩余部分
                l1.next = self.mergeTwoLists(l1.next, l2) # 递归调用记得用self
                # 当前递归层的返回值：返回处理过的当前节点
                return l1
            else:
                l2.next = self.mergeTwoLists(l1, l2.next)
                return l2

递归注意事项

这里判断哪个节点值更小后，需要保留的是这个更小的节点，并且递归处理其下一个节点
所以应该写成l1.next = self.mergeTwoLists(l1.next, l2) # 等于迭代法中的curr.next = l1，而不是l1 = self.mergeTwoLists(l1.next, l2)

对于合并两个有序链表的递归解法，我们可以分析其时间复杂度和空间复杂度如下：

复杂度分析

时间复杂度：
- 最坏情况：在最坏的情况下，我们需要遍历并比较两个链表中的所有节点一次。这通常发生在两个链表长度相近且每次比较都不得不考虑两个链表中的元素时。如果两个链表的长度分别为 m 和 n，那么时间复杂度为 O(m + n)，因为每个节点只被访问一次。

空间复杂度
- 递归栈空间：递归的主要空间开销来自于递归栈。在最坏情况下（即递归深度最大时），递归的深度等于两个链表的长度之和。因此，在递归过程中，最大的栈空间为 O(m + n)。这是因为每进行一次递归调用，就需要在栈中保存一次函数调用的信息，直到达到基本情况。

总结

  • 时间复杂度：O(m + n)，其中 m 和 n 分别是两个链表的长度。这是因为需要遍历两个链表的每个节点一次。
  • 空间复杂度：O(m + n)，这主要是由于递归调用栈的深度，可能会达到两个链表长度之和的情况。在递归解法中，空间复杂度通常由递归深度决定。

值得注意的是，尽管递归方法在代码简洁性和可读性方面有显著优势，但在处理非常长的链表时，由于空间复杂度较高，可能会导致栈溢出。在实际应用中，根据具体情况选择适合的方法是非常重要的。
