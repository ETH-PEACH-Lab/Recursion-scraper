Recursion with a better efficiency | 28ms (96.9%)

Intuition

The following is the nth row for n = range(3, 8):


We can observe that the values on the second half will always be the opposite of that of the first half:


Most recursive or looping approaches repeatedly halve the row until n == 1 to derive the kth symbol, but that'll take n turns to complete.

What we actually need is just the smallest possible length of sequence that can separate k into the second half, so as to figure out the kth symbol by evaluating the corresponding value in the first half. Rinse and repeat.

  • "n = 7, k = 55"

    min length of seq needed to split 55 is 64
    k = k - 64/2 = 23
    min length of seq needed to split 23 is 32
    => k = k - 32/2 = 7
    min length of seq needed to split 7 is 8
    => k = k - 8/2 = 1
    **only 3 loops are needed instead of 7

  • "n = 20, k = 555"

    min length of seq needed to split 555 is 1024
    => k = k - 1024/2 = 43
    min length of seq needed to split 43 is 64
    => k = k - 64/2 = 11
    min length of seq needed to split 11 is 16
    => k = k - 16/2 = 3
    min length of seq needed to split 3 is 4
    => k = k - 4/2 = 1
    **only 4 loops are needed instead of 20

This approach can be as much as 10 times faster if k is at the optimized position, and the advantage will be more significant when n extends beyond its maximum value 30.

Approach

The minimum length of sequence needed can be found by:

minLen = 2 ** ( math.ceil ( log ( k , 2 ) ) - 1 )

Then update k,

k = k - minLen // 2

Or, you can merge them into one line:

k = k - 2 ** math.trunc ( log ( k-1, 2 ) )

The value of n is irrelevant in this approach.

Complexity

  • Time complexity:
    O ( log ( k , 2 ) )

  • Space complexity:
    O ( log ( k , 2 ) )

Code

class Solution:
    def kthGrammar(self, n: int, k: int) -> int:
        if k == 1:
            return 0
        return 1 - self.kthGrammar(n, k - 2 ** trunc(log(k-1, 2)))
