1823. 找出游戏的获胜者

这种题目类似的题型很多，还有一种叫是击毙的，套路都一样的，每轮都减少一个固定循环位置，问最后剩谁；

这类问题其实最简单就是开个数列模拟，顶多就 $O(n^2)$ ，一般不会是最后一题，大概率不会超时，但我们本质精益求精的态度，把这个类似递归的循环拆开来分析一下；

简单用例： n = 5 ， k = 3

这里 k = 3 意为从第一个元素开始选第 3 个，但是按下标算的话，实际选的是下标 2 ，那么设 pick = k - 1 表示真正选中的下标，那么当长度小于 pick ，例如长度是 length = 3 而 pick =5，那么实际最后选中位置就是 finalPick = pick % length。好了前提条件都说完了；

我们完整模拟一下整个过程

然后我们动用超能力时刻回溯从最后结果倒推，一开始这个人站在哪里

因为最后次胜出时下标必然是 0 ，想办法反推回去。

一开始，长度是 1，下标是 0 ；

当前这个状态是因为，前一次删掉一个后旋转（轮转）数组才变成上面这样的，所以第一步我们得先把那个被删的加上去，还原一下数量，但具体数字我们不知道也不需要知道；

虽然我们不知道下标应该是多少，也就是应该旋转（轮转）多少下；
但我们知道这个红框它应该在什么地方，因为每次选择必然是第一个元素开始选第 k 个
根据刚刚的公式： $pick = k - 1,\ finalPick = pick\ \%\ length$
所以 $finalPick = 2\ \%\ 2 = 0$ ，所以红框就是应该在 下标0 的位置上，那么本轮开始时，我们的主角在下标1

然后继续回溯，那么在倒数第 3 轮的时候长度应该是 3 ，所以还是一样的套路先补够数量；

同样的，虽然目前红框在 下标0 的位置是因为这是删掉后的情况，但实际它被删前的位置应该是 $finalPick = pick\ \%\ length = 2\ \%\ 3 = 2$ 它应该在 2 那里，那么如果让它去到 2 呢？我们旋转（轮转）一下数组就行了，可以理解为数组前后相连一起往左移动，那么除了最后一个到了前面其他都挪了两下；

那么很显然继续这样搞就能一直还原到想要的最开始状态；

当长度为 4 时 $finalPick = pick\ \%\ length = 2\ \%\ 4 = 2$ ；

当长度为 5 时 $finalPick = pick\ \%\ length = 2\ \%\ 5 = 2$ ；

那么再次细化和总结一下步骤：

  1. 补齐当前队列数量，实际操作就是当前主角的下标 +1 ，因为加入的都是头部加入，后面全部元素下标都 +1；

  2. 计算出新加入的这个元素在本轮前的位置，实际就是它被删的位置，finalPick = pick % length ；

  3. 旋转这个数组贴合这个结果，实际操作不需要真的旋转，因为我们已经知道当前需要移动的那个对象在下标 0，它要移动到 finalPick ，这个移动距离其实就是 finalPick 本身，而我们实际要移动的是主角本身，故主角下标 + finalPick 然后 % length 就是本轮答案了；

  4. 循环直到还原到原长度；

```python [ - ]
class Solution:
def findTheWinner(self, n: int, k: int) -> int:
if n == 1: return 1
pick, index = k - 1, 0
for length in range(2, n + 1):
newIndex = index + 1
pickIdx = pick % length
index = (newIndex + pickIdx) % length
return index + 1

```JavaScript [ - JS 短小精悍]
const findTheWinner = (n, k) => Array(n + 1).fill(0).reduce((a,b,length)=> (a + k) % length) + 1;
